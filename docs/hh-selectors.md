# hh.ru — карта селекторов

Снята 2026-08-29 с живого залогиненного профиля (`scripts/capture-hh.ts`) в фикстуры
`tests/fixtures/hh-search.html` и `tests/fixtures/hh-vacancy.html`.

Запрос выдачи: `бизнес-аналитик`, `area=1` (Москва). 50 вакансий на странице.

**Предпочитать `data-qa` классам.** У hh.ru классы генерируются сборкой и меняются от
релиза к релизу, `data-qa` держатся годами. Все селекторы ниже подтверждены подсчётом
вхождений в снятых фикстурах — это не догадки.

## Страница выдачи (`/search/vacancy`)

| Что | Селектор | Вхождений | Заметки |
|---|---|---|---|
| Карточка вакансии | `[data-qa="vacancy-serp__vacancy"]` | 50 | корень карточки, всё остальное искать внутри |
| Ссылка на вакансию | `a[data-qa="serp-item__title"]` | 50 | `href` содержит `/vacancy/{id}` — отсюда берётся `sourceId` |
| Заголовок (текст) | `[data-qa="serp-item__title-text"]` | 50 | |
| Работодатель | `[data-qa="vacancy-serp__vacancy-employer-text"]` | 50 | есть ещё `-employer` — это ссылка-обёртка |
| Локация | `[data-qa="vacancy-serp__vacancy-address"]` | 50 | город плюс, иногда, метро |
| Зарплата | `[data-qa="vacancy-serp__compensation"]` | **1** | **см. предупреждение ниже** |
| Кнопка отклика в выдаче | `[data-qa="vacancy-serp__vacancy_response"]` | 50 | в адаптере не используется — отклик идёт со страницы вакансии |
| Опыт | `[data-qa^="vacancy-serp__vacancy-work-experience"]` | 31 | суффикс кодирует диапазон, напр. `between3And6` |

**Зарплата встречается 1 раз на 50 карточек.** Это не поломка селектора — подавляющее
большинство вакансий в этой выдаче зарплату не показывают. Адаптер обязан считать
зарплату отсутствующей по умолчанию и не падать, когда её нет. Скорер зарплату не
использует, так что на отбор это не влияет.

## Не снято — форма отклика

`vacancy-response-link-top` — это всё, что известно про подачу. Форма, которая
открывается после клика (поле сопроводительного письма, кнопка отправки, выбор
резюме), в фикстурах отсутствует.

Причина не техническая: чтобы её увидеть, надо нажать «Откликнуться» на настоящей
вакансии в аккаунте пользователя, а оттуда до отправки реального отклика живому
работодателю — один клик. Это необратимое действие вовне, и решение о нём принимает
владелец аккаунта, а не автоматика.

Значит, неизвестны и три маркера, на которых держится защита адаптера:

- **признак «вы уже откликались»** — без него дедуп опирается только на локальную БД
  и не увидит откликов, поданных руками;
- **признак капчи** — на нём стоит вся остановка очереди;
- **признак успешной отправки**.

Пока они не сняты, `apply()` у адаптера `hh` возвращает честный `failed` со ссылкой,
ровно как у `hrge`. Первая же строчка после их снятия — переписать `apply()`.

**Когда будешь снимать: заблокируй отправку на уровне сети.** Playwright умеет
`page.route()` — повесить перехват на POST отклика и обрывать его. Тогда даже
случайный клик по «Отправить» физически не уйдёт с машины, а форму со всеми
селекторами видно целиком.

## Подача отклика — что выяснено ценой ошибки (2026-08-29)

**`POST /applicant/vacancy_response/popup` — это сама подача отклика, а не подгрузка формы.**

Выяснилось это плохим способом. При съёмке разметки формы этот путь был внесён в
whitelist сетевой блокировки — по догадке из его имени, где «popup» читается как
«показать модалку». На деле, когда у соискателя есть резюме и сопроводительное
письмо не обязательно, hh.ru подаёт отклик **сразу по нажатию «Откликнуться»**,
безо всякой промежуточной формы. С аккаунта ушёл настоящий отклик на вакансию
`136701903` (БАНК УРАЛСИБ), без письма. Отменить отклик на hh.ru нельзя.

**Правило, которое из этого следует:** имя эндпоинта ничего не доказывает.
Модифицирующий запрос считается необратимым, пока не доказано обратное — а
доказать это, не выполнив его, обычно нельзя. Значит whitelist в
`scripts/capture-hh-response-form.ts` пуст и должен таким остаться.

### Что это даёт адаптеру

Контракт подачи, в отличие от hr.ge, теперь известен:

| Что | Значение |
|---|---|
| Эндпоинт подачи | `POST https://hh.ru/applicant/vacancy_response/popup` |
| Триггер в UI | клик по `[data-qa="vacancy-response-link-top"]` (брать `.first()`) |
| Промежуточная форма | **отсутствует**, если есть резюме и письмо не обязательно |
| Признак успеха | `[data-qa="vacancy-response-success-standard-notification"]` |
| Предложение приложить письмо (после подачи) | `[data-qa="responded-success-attach-cover-letter"]` |
| Ссылка на отклик | `[data-qa="vacancy-response-link-view-topic"]` |
| Нет резюме | `[data-qa="vacancy-label-no-resume"]` |

Фикстура: `tests/fixtures/hh-response-sent.html` — состояние страницы **после**
успешной подачи. Названа честно: это не форма, это результат.

### Нерешённое: куда девать сопроводительное письмо

Вся система построена вокруг того, что человек одобряет **письмо**. Но на этом
пути письмо не отправляется вовсе — hh.ru предлагает приложить его отдельно, уже
после подачи (`responded-success-attach-cover-letter`).

Значит `apply()` для hh.ru нельзя писать как «клик по Откликнуться». Нужен путь,
на котором письмо уходит вместе с откликом. Кандидаты, ни один не проверен:

1. Открывать форму принудительно (у hh.ru есть отдельный маршрут отклика с письмом).
2. Подавать, затем прикладывать письмо вторым шагом — но тогда работодатель может
   увидеть отклик без письма раньше, чем письмо появится.

Проверка любого из вариантов = ещё один настоящий отклик. Делать только с явного
разрешения владельца аккаунта и на заранее выбранной им вакансии.
