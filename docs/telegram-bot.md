# Telegram-бот кандидата

Второй, независимый канал: рекрутёр пишет боту сам. Поиск по каналам и первое
сообщение рекрутёру — это user-сессия GramJS (`src/telegram/`), бот их не
заменяет и заменить не может: Bot API не даёт читать историю чужих чатов и не
позволяет писать первым.

Дизайн: [`specs/2026-09-20-telegram-bot-design.md`](superpowers/specs/2026-09-20-telegram-bot-design.md).

## Что нужно один раз

`.env` рядом с `package.json`:

```
TG_BOT_TOKEN=...       # @BotFather → /mybots → API Token
TG_OWNER_CHAT_ID=...   # куда слать пинги; можно отдельный аккаунт
```

`chat_id` подскажет сам бот: запусти его, напиши ему что угодно — он напечатает
в консоль `chat_id этого собеседника: …`.

В `config.json` — блок `bot`: `profile.github`, `profile.telegram`, при желании
`models` и `limits`.

В BotFather (Bot Settings): Group Privacy оставить включённой, Allow Groups —
выключить (бот нужен только в личке), Inline Mode — выключить. Вебхук не
ставить: бот работает на long polling и при найденном вебхуке честно откажется
стартовать.

## Запуск

```bash
npm run bot
```

Круглосуточно — через планировщик задач:

```bash
powershell -ExecutionPolicy Bypass -File scripts/bot-service.ps1
```

## Что бот делает

| Команда | Что |
|---|---|
| `/start` | текст и постоянная клавиатура из четырёх кнопок |
| `/cv` | PDF резюме специальности по умолчанию (дальше — по `file_id`) |
| `/profile` | ссылки из `config.json` |
| `/add_vacancy` | ждёт вакансию: текст, ссылку или файл `pdf`, `docx`, `txt`, `md` |
| (без команды) | ссылка на площадку или текст, похожий на вакансию, обрабатывается как вакансия — рекрутёры инструкций не читают |
| `/set_meet` | ждёт дату и время в свободной форме, отвечает «Записал: …» и пингует владельца |

Дата и время у `/set_meet` — без формата: «10 октября в 15:00», «10.10 в час дня»,
«завтра в 3», «в пятницу в 14:30», «на следующей неделе во вторник в 11», а
прежний `дд.мм;чч:мм` тоже понимается. Разбор — правила, без модели (`src/bot/meet.ts`),
поэтому он работает и при исчерпанных лимитах. Две догадки: «в 3» без «утра/дня/вечера»
читается как 15:00 (часы 1–7 — дневные), дата без года — ближайшая в будущем.
Рекрутёр видит разобранное время в подтверждении («Записал: 10 октября (суббота),
15:00»), а владелец — в пинге, рядом со словами рекрутёра. Не поняли — бот
переспрашивает: нет даты, нет времени или время уже прошло.

Свободный вопрос — ответ модели строго по фактам резюме. Не по теме — шаблон.

## Пинги владельцу

Бот пишет в `TG_OWNER_CHAT_ID` (сейчас — личный аккаунт @ll_larr; этот аккаунт
должен хоть раз нажать «Start» у бота, иначе Telegram не даст писать первым).
Пинг один — **о назначенном собеседовании** (решение владельца 2026-10-05); о
присланной вакансии и обо всём остальном бот не пишет, вакансия просто ложится
в очередь панели.

В пинге: разобранное время («10 октября (суббота), 13:00»), `@username`
рекрутёра, его слова дословно («Он написал: «10.10 в час дня»») и вакансия: номер,
название, когда прислана. Если вакансия прикреплялась, её полный текст приходит
файлом `vacancy-<номер>.txt`, а пинг — подпись к нему. Файл не загрузился — пинг
уходит обычным сообщением. Название берётся из очереди в любом статусе: к
собеседованию строка часто уже `skipped`.

Запись о собеседовании делается до отправки и повторяется на каждом круге, пока
Telegram не примет пинг. Бот привязывает собеседование к последней вакансии,
присланной из того же чата: у чата, из которого владелец сам проверял бота,
эта привязка остаётся старой.

## Границы, которые нельзя размывать

- **У модели нет инструментов.** Ни файлов, ни сети, ни базы. Ключ живёт в
  HTTP-заголовке, а не в промпте.
- **Вакансия из бота не автоодобряется никогда.** `selectAutoApprovals`
  пропускает `source = 'tg-bot'` независимо от тумблера: текст прислал
  незнакомый человек, и он мог быть написан под инъекцию.
- **Файл — это байты.** Разбор идёт в отдельном процессе с таймаутом, тип
  проверяется по расширению, MIME и сигнатуре, файл удаляется сразу.
- **Страницы площадок читает браузер.** `hh.ru` и соседи отдают обычному
  запросу только шапку сайта, описание рисует JS, а `api.hh.ru` отвечает `403`
  (снято 2026-09-20). Для таких ссылок поднимается отдельный headless-Chromium
  — не персистентный профиль, иначе бот заблокировал бы `npm run search`.
  Прочитанное проверяется на «похоже на вакансию»: заглушка и страница логина
  до модели не доходят.
- **Ссылки — по белому списку.** Иначе `http://127.0.0.1:3000/api/queue`
  превратил бы бота в читалку твоей панели.

## Лимиты

`config.json` → `bot.limits`: 20 ответов модели на чат в сутки, 200 на бота,
не чаще сообщения в 3 секунды, 5 страйков — сутки молчания, 3 записи о
собеседовании на чат в сутки. Счётчики — в `queue.db`, перезапуск их не
обнуляет. `/cv`, `/profile` и `/set_meet` работают всегда: они не стоят денег.

## Секретарь: ответы в личке @HIRE_agent

Дизайн: [`specs/2026-10-09-secretary-bot-design.md`](superpowers/specs/2026-10-09-secretary-bot-design.md).

Бот подключён к рабочему аккаунту через Telegram Secretary Mode (в клиенте:
Настройки → Chat Automation → бот `@lar_autoapply_bot`). С этого аккаунта
GramJS-сессия пишет рекрутёрам первой; их ответы в личке теперь видит и
обрабатывает бот. Он не пишет первым и не отвечает позже 24 часов после
последнего входящего сообщения — так устроен Telegram.

`config.json` → `bot.secretary.account` — username аккаунта без `@`
(сейчас `HIRE_agent`). Нет блока — секретаря нет, бот работает только в своём
чате. Остальные поля необязательны: `debounceMs`, `maxDebounceMs`,
`memoryTurns`, `memoryTtlMinutes`, `maxRepliesPerChatPerHour`, `replyWindowHours`.
Тумблеры — в панели, вкладка «Настройки»: «Секретарь», «Календарь», «Дожимы»,
«Ящик откликов hh.ru». После правки `config.json` бот перезапускается:

```bash
powershell -ExecutionPolicy Bypass -File scripts/bot-restart.ps1
```

Проверка, что Telegram видит подключение: `npx tsx scripts/bot-whoami.ts`
(только чтение: `getMe` и `getWebhookInfo`; в `allowed_updates` должны быть
`business_connection`, `business_message`, `edited_business_message`).

### Что делает секретарь

Порядок: приветствие/«спасибо»/прощание (готовые тексты, не чаще раза в 6 ч) →
вакансия (ссылка или файл — в очередь, не одобряется никогда) → встреча
(`parseMeetTime`) → просьба о резюме (PDF) → вопрос только о фактах (строки из
`data/facts.md`, без модели) → модель с гейтом TOPIC и валидаторами. Модель не
выдумывает числа и обещания; не ответила — уходит дословная отписка владельца.

- **Контекст.** Последние реплики хранятся в памяти процесса (`memoryTurns`,
  `memoryTtlMinutes`) и не пишутся на диск. Вакансия — та, по которой мы писали.
- **Встречи.** Одно время — запись и пинг владельцу (с `.ics`, если включён
  календарь). Два времени, отрицание, прошедшее — просим назвать одно. Перенос —
  новая запись, прежняя `superseded_at`. Отмену без нового времени не
  автоматизируем.
- **Календарь** (`settings.calendar`, по умолчанию слоты выключены): рабочие дни и
  часы, длительность, буфер между встречами, минимальное время до встречи,
  горизонт. Включён — бот предлагает свободные слоты и не записывает на занятое.
  Напоминание владельцу — за заданное число минут.
- **Антипетля.** Не больше `maxRepliesPerChatPerHour` ответов на чат в час;
  повтор того же текста за час без ответа; свои сообщения аккаунта ответа не вызывают.
- **Тексты не хранятся.** В `queue.db` только метаданные: кто, когда, чем кончилось.

### Вкладка «Диалоги»

Воронка за 8 недель (отправлено → ответил → собеседование), диалоги за 30 дней
(личка и чаты hh), блок дожимов и блок «Ящик откликов hh.ru». У hr.ge и
careerist ответов боту нет — у них только «отправлено».

### Дожимы

Одно напоминание на контакт, тумблер **выключен по умолчанию**. Уходят с
GramJS-сессии (бот первым писать не может), под общим дневным лимитом
`throttle.tg`. Перед отправкой читается живая история чата: кто уже ответил —
тому дожим не уходит; история не прочиталась — не уходит тоже (fail-closed).

```bash
npm run followups                  # список: кому пора и какие есть черновики
npm run followups -- prepare       # написать тексты (шаблон или модель)
npm run followups -- send [--id N] # отправить; без тумблера отказывает
```

### Что не проверено вживую

Ночная реализация шла без доступа к чужому аккаунту. Вживую не сняты: форма
апдейтов `business_message` и `business_connection`; текст ошибки при ответе
вне 24 часов; `getFile` для документа из лички; `sendMediaGroup` владельцу;
разметка чата hh.ru (см. `docs/hh-selectors.md`). Первое реальное сообщение
рекрутёру — повод посмотреть лог бота: `data/bot-service.log`.
