## 1. Задача и границы

ГигаРекрутёр — скрининг-бот Сбера в Telegram. После отклика на вакансию Сбера
он сам пишет кандидату в личные сообщения и задаёт вопросы по резюме: почему
ищешь работу, зарплатные ожидания, детали конкретного инструмента, пробелы в
занятости. Живой прогон 2026-09-15 дал шесть вопросов, из них два уткнулись в
факты, которых в резюме нет.

Задача: отвечать на эти вопросы автоматически, от имени владельца, без его
участия.

**Почему не бот.** Telegram не даёт боту писать первым и не даёт боту
переписываться с другим ботом. Второй бот владельца до ГигаРекрутёра не
достучится никогда, при любом коде. Это то же ограничение, что уже записано в
`docs/telegram-bot.md`. Единственный работающий транспорт — user-сессия MTProto
(`src/telegram/gramjs.ts`).

**Отдельная сессия личного аккаунта (G1, 2026-09-27).** ГигаРекрутёр пишет в
личный аккаунт владельца (`@ll_larr`), а `data/telegram.session` авторизована
рабочим аккаунтом `@HIRE_agent`: с неё `TelegramAdapter` ищет вакансии по
каналам и пишет рекрутёрам первым, и она остаётся рабочей. Интервью идёт со
своей сессии личного аккаунта — файл `gigarecruiter.sessionPath`, по умолчанию
`data/telegram-interview.session`. Вход в неё — руками владельца:
`npm run tg:login -- --session data/telegram-interview.session` (без аргумента
`tg:login` по-прежнему пишет рабочую сессию). Молча записать личный аккаунт в
рабочую сессию нельзя (I1): `npm run tg:login --session=…` без «--» npm
забирает флаг себе (`npm_config_session`) — скрипт отказывается и называет
правильную команду; живую непустую `data/telegram.session` вход перезаписывает
только с `-- --force`. Пока файла нет, каждый запуск
пишет в журнал одну строку «нет сессии личного аккаунта — войди: …» и
выходит, не трогая ни VPN, ни Telegram.

**Охват — один username.** Белый список из одного бота. Ни живым рекрутёрам, ни
другим скрининг-ботам эта машина не отвечает.

**Вне этой спеки:**

- автоответчик в личке живым рекрутёрам (решено 2026-09-25: отдельной задачей,
  со своей спекой; сейчас входящих в личке не обрабатывает никто);
- нажатие любых кнопок в чате с ГигаРекрутёром, кроме одного вида — варианта
  в подсказке выбора вакансии (G2, см. 7);
- хранение стенограммы диалога в файлах;
- ответы голосом, файлами, реакциями.

### 1.1 Две формы ответа

Канала будет два, и форма ответа у них **разная**. Это не одна механика с
флагом — это два разных контракта, и путать их нельзя.

| | ГигаРекрутёр (эта спека) | Личка живым рекрутёрам (будущая спека) |
|---|---|---|
| Собеседник | скрининг-бот, ждёт ответа по существу | человек, терпит паузу |
| Форма | развёрнутый ответ на вопрос интервью | короткий ответ или вежливая отписка |
| Провал моделей | **молчим** и повторяем, владельца не трогаем | отписка дословно (см. ниже) |
| Заглушка в чат | никогда | допустима и предусмотрена |

Текст отписки для лички, продиктован владельцем 2026-09-25 дословно, менять
без него нельзя:

> извините, сейчас занят; воспользуйтесь @lar_autoapply_bot, если вопрос срочный.

**Следствие для реализации.** Политика отказа — параметр, а не константа внутри
`interview.ts`. Генерация ответа и валидатор общие, поведение при провале
задаёт вызывающая сторона. Иначе будущая личка либо унаследует молчание
ГигаРекрутёра, либо протащит отписку туда, где она запрещена.

## 3. Триггер и расписание

1. `npm run send` отправил отклик на вакансию Сбера — в состояние пишется
   `windowUntil = now + 2ч`.
2. Внутри окна работает живой демон: подписка на входящие от одного peer,
   ответ через секунды после вопроса.
3. Нет новых сообщений 10 минут — сессия закрывается, демон гаснет.
4. Дальше поллинг раз в 4 часа: короткий подъём, `getMessages` с
   `minId = lastMessageId`. Есть новое — окно открывается заново и цикл
   возвращается в пункт 2.
5. Первый запуск 2026-09-25 в 22:40 через планировщик задач Windows
   (`scripts/interview-service.ps1`). Окно держится до 00:40, первый поллинг
   там же, дальше каждые 4 часа.

Задержка перед каждым ответом — случайная величина из `replyDelaySec`
(по умолчанию 40–120 секунд) плюс `setTyping`. Мгновенный ответ на вопрос про
идемпотентность в Kafka выдаёт машину.

## 4. Модули

Раскладка следует репозиторию: чистая логика в `src/core`, MTProto в
`src/telegram`, команда в `cli.ts`.

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `src/core/facts.ts` | читает `data/facts.md`, отдаёт текст и белый список чисел | — |
| `src/core/interview.ts` | сборка промпта, перебор моделей, валидатор | `facts.ts`, `openrouter.ts`, `letter.ts` |
| `src/core/vpn.ts` | статус VPN и рестарт его службы (`sc.exe stop/start`, с 2026-09-26 — Happ) | `proxy.ts` |
| `src/telegram/interview-session.ts` | подписка на входящие от одного peer, история чата, `setTyping`, отправка; открывается с сессии личного аккаунта (`gigarecruiter.sessionPath`, G1) | `gramjs.ts`, `types.ts` |
| `src/core/interview-choice.ts` | выбор вакансии (G2): узнать подсказку, выдержка, какой вариант жать | `interview-session.ts` (тип) |
| `src/core/interview-runner.ts` | окно, тишина, поллинг, состояние, повторы | всё выше |

Границы жёсткие: `interview.ts` ничего не знает про Telegram,
`interview-session.ts` ничего не знает про модели. В `src/telegram/types.ts`
уже есть интерфейсы `TgReader` и `TgSender` — подменяются фейками, вся логика
тестируется без сети.

Команда: `npm run interview` (`src/cli.ts interview`).

## 5. Промпт и база фактов

Контекст диалога берётся из самого чата через GramJS, а не из файла.
Стенограмма не ведётся — историю хранит Telegram, и после рестарта демона она
никуда не девается.

Сообщения к модели:

- **system** — правила ответа, текст резюме, текст `data/facts.md`;
- **далее** — весь транскрипт диалога, прочитанный из чата;
- **user** — последний вопрос ГигаРекрутёра.

`data/facts.md` покрывает то, чего в резюме нет. Черновик собирается из резюме,
`config.json` и живого диалога 2026-09-15, пустые поля владелец заполняет
руками. Минимальный состав: пробелы в занятости с объяснением, зарплатная
вилка, гражданство, готовность к офису и гибриду, срок выхода, уровень
английского, годы учёбы, готовность к тестовому заданию.

Факт, которого нет ни в резюме, ни в базе, модель не имеет права придумать.
Валидатор это ловит, а не промпт.

## 6. Валидатор

Ответ проходит четыре проверки. Любая отбраковывает ответ целиком и запускает
следующую модель.

1. **`findForbiddenClaim`** из `src/core/letter.ts` — уже написан, ловит
   приписанные навыки.
2. **Белый список чисел.** Собирается из резюме, `data/facts.md` и текста
   самого входящего вопроса. Любая цифра в ответе, которой там нет, —
   отбраковка. Это ловит главное: модель округляет «85,5%» до «около 90%» и
   сдвигает годы. Числа словами («две части», «три вещи») не трогаем, только
   цифры, проценты и годы.
3. **Длина** — до 1500 символов. Живые ответы 2026-09-15 укладывались в
   700–900.
4. **Маркеры автомата** — «как языковая модель», «не могу ответить»,
   «уточните вопрос». Наружу не уходит.

Дополнительно переиспользуется `findLeak` из `src/bot/reply.ts`: ключ, путь,
имя секрета, кусок системного промпта в ответе — отбраковка.

## 7. Отказы

### Модели

**Правило: в чат уходит только прошедший валидацию ответ. Заглушка — никогда.**
Правило относится к ГигаРекрутёру. У лички будет своя политика с отпиской —
см. 1.1.

Раунд — перебор всех моделей из конфига. Раунд провалился:

1. Проверка статуса моделей: отличить «модель не ответила» (сеть, ключ,
   таймаут) от «ответ не прошёл валидатор» — это разные болезни и лечатся
   по-разному.
2. Строка в `data/interview.log`: что сломалось, какая модель, какая проверка.
3. Повтор раунда с бэкоффом 30 с, 2 мин, 5 мин, 15 мин, дальше каждые 15 мин,
   пока открыто окно.

`setTyping` при повторах не держится: фальшивое «печатает» на полчаса выглядит
хуже молчания.

**Осознанная цена.** Пока идут повторы, в чате тишина, и ГигаРекрутёр может
закрыть диалог сам. Владелец выбрал «не врать» вместо «не молчать» — размен
верный, но он реальный.

### VPN

`discoverSocksProxy` вернул пусто — `vpn.restart()` перезапускает службу VPN
(решение владельца 2026-09-26: клиент теперь Happ).

Соединение держит служба Windows `HappService` («Happ Proxy Client Service»,
`D:\Happ\happd.exe`, LocalSystem, автозапуск); ядро `xray.exe` — её дочерний
процесс, слушает 127.0.0.1:10808–10810, и `discoverSocksProxy` находит его по
маске `VPN_PROCESS`. Права службы дают обычному пользователю и остановку, и
запуск, так что перезапуск идёт без прав администратора. Одна попытка:

1. `sc.exe stop HappService`;
2. ждать, пока `sc.exe query HappService` сообщит `STOPPED`, — до 15 секунд,
   опрос раз в секунду; не дождались — всё равно идём дальше;
3. `sc.exe start HappService`;
4. если GUI `D:\Happ\Happ.exe` не запущен — запустить его
   (`cmd /c start "" D:\Happ\Happ.exe`): возможно, именно он велит службе
   подключиться;
5. ждать появления порта до 30 секунд, опрос раз в 2 секунды.

Коды выхода `sc.exe` решающими не считаются (остановка уже остановленной
службы — 1062): успех решает только появившийся порт. Три попытки с бэкоффом
5 и 15 секунд между ними, после последней — без паузы. Не поднялся — цикл спит
до следующего поллинга, строка в `data/interview.log`.

Прежний клиент v2RayTun может оставаться установленным и висеть в трее — его
цикл не трогает никогда: ни убийства процессов, ни запуска.

Без VPN Telegram недоступен физически: отвечать всё равно нечем, деградации
тут нет.

### Telegram

- `FLOOD_WAIT` — уважаем, потолок `MAX_FLOOD_WAIT_S` уже есть в
  `src/adapters/telegram.ts`.
- Сессия протухла — остановка цикла и строка в `data/interview.log`. Лечится
  только руками: `npm run tg:login -- --session data/telegram-interview.session`
  (сессия личного аккаунта, G1; журнал называет именно её файл, чтобы вход не
  перезаписал рабочую сессию). Владельцу никто об этом не сообщает —
  см. раздел 10, это принятый риск.
- Кнопки и клавиатуры в чате не нажимаются и не отвечаются — с одним
  исключением (решение контроллера G2, 2026-09-27, заменяет прежнее «выбор
  вакансии уже определён откликом»). Оценка бота звёздами — дело владельца, не
  машины: её кнопки не нажимаются никогда.

#### Выбор вакансии (G2)

Когда откликов несколько, ГигаРекрутёр не начинает интервью, пока не выбрана
вакансия: присылает «Вижу, что вы откликнулись на несколько вакансий. По какой
из них хотели бы продолжить диалог? …» с инлайн-кнопками «1. …», «2. …» и
«Далее». Живой конец интервью — три сообщения одной секундой: прощание,
«Пожалуйста, оцените мою работу!» со звёздами и эта подсказка. После выбора
бот правит саму подсказку на месте в «Спасибо за выбор вакансии! …» (кнопки
сняты) и следом присылает начало интервью «… Получил Ваш отклик на позицию X …».
Иногда бот выбирает сам в первую минуту, иногда подсказка висит днями. Когда
вакансия осталась одна, подсказки нет вовсе: прощание, оценка и сразу начало
нового интервью «… Получил Ваш отклик на позицию Data analyst …» — одной минутой
(живое наблюдение 2026-09-27, 4:35).

Правила (`src/core/interview-choice.ts`):

1. **Подсказка** — входящее с кнопками, чей текст спрашивает, по какой
   вакансии продолжать (`/по как(ой|ую) из (них|вакансий)|выберите вакансию/i`),
   и не меньше двух его кнопок — **пункты нумерованного списка из этого же
   текста**: на кнопке «N. название», в тексте то же «N. название» (обрезанное
   в кнопке многоточием — по началу; «1. X» — не «11. X»). Подвал «сменить
   вакансию» подсказкой не делает: бот ставит его и под обычный вопрос интервью.
   Кнопка со словами оценки, звёзд, отмены, отказа или смены
   (`/оцен|звезд|звёзд|★|⭐|сменить|отмен|отказ/i`) вариантом не бывает никогда,
   даже из списка; кнопка без номера — тоже, из них жмётся только «Далее».
   Оценка (звёзды в тексте или в кнопках) подсказкой не бывает. Это
   единственный вид кнопок, который цикл жмёт (C1, 2026-09-27).
2. **Выдержка.** Жмём, только когда подсказка — последнее входящее в чате, ей
   не меньше 3 минут (по её дате в Telegram) и после неё ничего не пришло.
   Пришли «Спасибо за выбор…» или начало интервью — бот выбрал сам, не жмём.
   Пришло что-то другое — не жмём, подсказка разобрана. Окно или тишина не
   гасят сессию, пока идёт выдержка; в поллинге подсказка старше 3 минут
   жмётся сразу.
3. **Что жмём.** Варианты (правило 1) по порядку; первый, которого нет в
   `interviewedTitles` и который не вакансия идущего интервью `currentTitle`
   (сравнение без регистра, лишних пробелов, кавычек и нумерации, ё как е;
   обрезанное многоточием — по началу). Все видимые пройдены — «Далее», **один
   раз на подсказку в любом процессе**: её id и кнопки в момент нажатия
   хранятся в состоянии (`pagedPromptId`, `pagedSnapshot`, I2); пока страница
   прежняя — ждём, новая — решаем по ней без «Далее». Не осталось ничего — не
   жмём, строка в журнал, метка за подсказкой. Вариант начинает интервью:
   сверх потолка за окно (правило 8) он не жмётся.
4. **Перед нажатием** подсказка перечитывается по id: уже «Спасибо за выбор…» —
   выбрали без нас, не жмём; не подсказка — не жмём; по свежей подсказке
   решение другое (нет нужной кнопки) — не жмём в этот проход. Сразу за этим
   перечитывается история чата после подсказки: есть хоть что-то новое — в
   этот проход не жмём (M3), следующий решит по правилу 2.
   Жмётся только инлайн-кнопка с данными (`messages.GetBotCallbackAnswer`, как
   `MessageButton.click` в GramJS); кнопка обычной клавиатуры отправила бы свой
   текст сообщением, а в чат уходит только проверенный валидатором текст.
5. **Граница интервью.** Подсказка, её след «Спасибо за выбор…» и начало
   интервью — не конец интервью и не болтовня. Конец FU-9 их не глотает: метка
   встаёт перед ними. Текст до границы остаётся без ответа. Выбор — наш, бота
   или владельца (подсказка уже «Спасибо за выбор…») — снимает
   `interviewEndedAt`: начинается новое интервью. Обычный текст после оценки
   («Спасибо за оценку!») по-прежнему без ответа (FU-9). Поэтому запомненный
   конец не выходит до открытия Telegram: запуск читает чат, чтобы увидеть
   подсказку или начало, и без них выходит одной строкой. Свежий конец, за
   которым подсказки ещё нет, держит сессию 3 минуты 30 секунд от даты оценки
   (выдержка подсказки плюс 30 с, M1): история могла прочитаться между оценкой и
   подсказкой, которые бот шлёт одной секундой. Пришли подсказка или начало —
   разбираются как обычно; текст за это время — без ответа; не пришло ничего —
   одна строка и выход. Конец, найденный поллингом позже, сессию не держит.
6. **Вакансии.** Нажатый нами вариант пишется **сразу при нажатии** (C2): его
   название — в `currentTitle` и в `interviewedTitles`, не дожидаясь начала
   интервью (оно может назвать вакансию иначе или не прийти). Начало интервью
   «Получил Ваш отклик на позицию X» или «…на вакансию X» тоже пишет X в
   `currentTitle` и сразу в `interviewedTitles` (нужно, когда выбрал бот или
   владелец). X — без кавычек и разметки, до перевода строки или до точки, за
   которой пробел и заглавная, либо конец строки; точка в скобках или кавычках
   и после сокращения в одну-две строчные буквы не режет («Бизнес-аналитик (г.
   Москва)», «…, г. Москва»). Конец интервью (свежий и хвост) переносит
   `currentTitle` в `interviewedTitles` и очищает её.
   «Спасибо за выбор вакансии» и любая строка про выбор вакансии («по какой из
   них», «выберите вакансию», «сменить вакансию»), с кнопками или без
   («Пожалуйста, выберите вакансию из списка выше.»), — служебные: не вопрос,
   без ответа (M2). Кроме начала интервью: оно отвечается и с подвалом
   «сменить вакансию».
7. **Начало без подсказки.** Начало интервью — законное новое интервью, начатое
   ботом, даже сразу за свежим концом и при стоящем `interviewEndedAt` (живое
   наблюдение 2026-09-27): `interviewEndedAt` снимается, `currentTitle` — из
   него, на него отвечаем как обычно. Начало по вакансии, уже стоящей в
   `interviewedTitles`, тоже отвечается (бот решил спросить снова) и тоже
   считается в потолок.
8. **Потолок интервью за окно** (C2). Каждое начатое интервью — нажатый нами
   вариант или начало, присланное ботом, — считается в `interviewsInWindow`,
   один раз: начало вслед за нашим нажатием уже посчитано нажатием
   (`pressedPromptId`), одно и то же начало второй раз не считается
   (`lastStartId`). Сверх `maxInterviewsPerWindow` (по умолчанию 6) —
   потолок: вариант не жмётся, начало остаётся без ответа, `capTrippedAt` и
   строка в журнал; до нового окна не отвечаем, как с потолком ответов.
   Счёт обнуляет новое окно.
9. **Журнал** — только id и название вакансии: какая нажата, почему не нажато.

## 8. Конфиг и состояние

Блок `gigarecruiter` в `config.json`:

```json
{
  "gigarecruiter": {
    "username": "Giga_recruiter_bot",
    "windowMinutes": 120,
    "idleMinutes": 10,
    "pollHours": 4,
    "replyDelaySec": [40, 120],
    "maxReplyLength": 1500,
    "maxRepliesPerSession": 12,
    "maxInterviewsPerWindow": 6,
    "models": ["..."],
    "vpnService": "HappService",
    "vpnApp": "D:\\Happ\\Happ.exe",
    "sessionPath": "data/telegram-interview.session"
  }
}
```

`sessionPath` — сессия личного аккаунта, с которой идёт интервью (G1, см. 1);
необязательно, умолчание — `data/telegram-interview.session`. Рабочая сессия
`data/telegram.session` интервью не касается.

`maxRepliesPerSession` — потолок ответов за одно интервью (C1, FR-6);
`maxInterviewsPerWindow` — потолок начатых интервью за окно (C2, см. 7,
правило 8), по умолчанию 6. Оба необязательны, положительные числа.

Рабочий клиент — Happ (с 2026-09-26, раньше — v2RayTun): служба
`HappService` и GUI `D:\Happ\Happ.exe`. Оба поля необязательны, это и есть
умолчания. Hiddify не используется.

Технический журнал — `data/interview.log`: отказы моделей, отбраковки
валидатора, рестарты VPN, гашение сессии. Это не стенограмма: текстов диалога
там нет, только события цикла.

Состояние — `data/interview-state.json`, двенадцать полей: `lastMessageId`,
`windowUntil`, `lastPollAt`, `capTrippedAt`, `interviewEndedAt`,
`currentTitle`, `interviewedTitles`, `interviewsInWindow`, `lastStartId`,
`pressedPromptId`, `pagedPromptId`, `pagedSnapshot`. Нет поля или оно не того
типа — ноль, пустая строка или пустой список.
`lastMessageId` обновляется **до** отправки: падение на полпути не даст
ответить дважды на один вопрос. `capTrippedAt` — когда сработал потолок
ответов за сессию или интервью за окно; пока он не 0, ни один запуск не
отвечает до нового окна.
`interviewEndedAt` — дата сообщения с кнопками, которым закончилось интервью
текущего окна; пока оно позже открытия окна, ни один запуск не отвечает на
текст. `capTrippedAt` снимает только новое окно (отклик на Сбер или
`--window`); `interviewEndedAt` — новое окно, выбор вакансии или начало нового
интервью (G2, см. 7).
`currentTitle` — вакансия идущего интервью ('' — неизвестна),
`interviewedTitles` — нормализованные вакансии начатых интервью (нажатых и
начатых ботом; список строк, по умолчанию пустой); новое окно их не трогает.
`interviewsInWindow` — интервью, начатых в текущем окне (C2), обнуляет новое
окно. `lastStartId` — id последнего посчитанного начала интервью;
`pressedPromptId` — подсказка, где мы нажали вариант, пока его начало не
пришло (начало за нажатием не считается второй раз). `pagedPromptId` и
`pagedSnapshot` — подсказка, где нажата «Далее», и её кнопки в тот момент
(I2). Эти четыре новое окно не трогает.

## 9. Тесты

TDD, vitest, как во всём репозитории.

- валидатор режет выдуманное число и пропускает число из резюме, из фактов и
  из текста самого вопроса;
- валидатор ловит приписанный навык, утечку, длину, маркер автомата;
- отбраковка переключает на следующую модель; провал всех моделей не шлёт в чат
  ничего и ставит повтор с бэкоффом;
- `lastMessageId` не даёт ответить дважды после рестарта демона;
- тишина 10 минут гасит сессию, окно 2 часа держит, поллинг встаёт на 4 часа;
- рестарт VPN: три попытки, бэкофф, отказ;
- сквозной прогон на фейковых `TgReader` и `TgSender`; фикстура — шесть
  реальных вопросов 2026-09-15, включая зарплату и пробел 07–12.2025.

## 10. Риски

**Бан аккаунта.** Это автоматизация личного аккаунта владельца через MTProto.
Telegram за такое теоретически банит. Репозиторий уже пишет рекрутёрам с
user-сессии, риск не новый, но он есть и им принят.

**Расхождение показаний.** Владелец не видит, что машина наговорила
(стенограмма отключена по его решению). На живом интервью ответы могут
разойтись. Смягчается тем, что источник ответов — только резюме и
`data/facts.md`, то есть то же, что владелец скажет сам.

**Тихая смерть.** Уведомлений владельцу нет по его решению 2026-09-25. Значит
протухшая сессия, недоступный VPN или упавший OpenRouter не разбудят никого:
цикл просто перестанет отвечать, а ГигаРекрутёр закроет диалог. Единственный
след — `data/interview.log`, и смотреть его нужно самому. Это цена полной
автономности, принятая сознательно.

**Пустая база фактов.** Незаполненный `data/facts.md` делает валидатор
единственной защитой: модель промолчит там, где могла бы ответить. Качество
автоответа равно качеству базы фактов.
