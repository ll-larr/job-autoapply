# Конвейер откликов

Полуавтоматическая подача резюме. Система ищет вакансии, отсеивает нерелевантные,
пишет сопроводительное под каждую и кладёт в очередь. **Отправляет только то, что
человек одобрил руками.**

Репозиторий: `C:\Users\lar\job-autoapply`.

## Железные правила

1. **Никогда не запускай `send` без явной просьбы пользователя в текущем разговоре.**
   Отклик на hh.ru необратим: отозвать нельзя, работодатель видит его сразу. Одна
   сессия уже отправила отклик по своей инициативе, разрешив запрос, о назначении
   которого только догадывалась по его имени. Правило оттуда: **имя эндпоинта ничего
   не доказывает**, модифицирующий запрос считается необратимым, пока не доказано
   обратное.
2. **Капчу не обходить.** Обнаружил — остановись и позови человека.
3. **Пароли не вводить.** Аутентификация только через профиль, куда пользователь
   залогинился сам (`npm run login`, если профиль протух).
4. **Письма — творческий выход пользователя.** Молчание не считается одобрением.
   Если он не оценил письма, спроси прямо.

## Перед любым запуском

Три вещи ломают прогон чаще всего. Проверь их, прежде чем диагностировать что-то ещё.

**Ключ.** Читается из `OPENROUTER_API_KEY`. Переменная выставлена в User-области,
и в уже открытом терминале её может не быть:

```powershell
$env:OPENROUTER_API_KEY = [Environment]::GetEnvironmentVariable("OPENROUTER_API_KEY","User")
```

Без ключа прогон не падает: вакансии попадут в очередь с пустыми письмами.

**Прокси.** Без него запросы к OpenRouter возвращают `403 "Access denied by security
policy"` — это блок-страница провайдера, **не ошибка API и не проблема ключа**.
Настраивать ничего не нужно: программа ищет прокси сама, в момент запроса
(`src/core/proxy.ts`), и при старте печатает, что нашла. Если VPN выключен, в
панели висит полоса «включи VPN»; перезапуск после включения не нужен.

**Залипший браузер.** `launchPersistentContext` держит каталог профиля эксклюзивно.
Прерванный прогон оставляет Chromium висеть, и следующий падает с «профиль занят»:

```powershell
Get-Process chrome | Where-Object { $_.Path -like "*ms-playwright*" } | Stop-Process -Force
```

## Команды

| Задача | Команда |
|---|---|
| Найти вакансии и наполнить очередь | `npm run search -- --limit 6` (фразы всех включённых специальностей; 6 — сколько попадёт в очередь) |
| Одна фраза от имени специальности | `npm run search -- "product manager" --specialty "Менеджер продукта" --limit 6` |
| Панель одобрения | `npm run panel` → http://127.0.0.1:4321 |
| Отправить одобренное | `npm run send` |
| Что в очереди | `npm run status` |
| Аварийная остановка | `npm run stop` |
| Перелогиниться | `npx tsx scripts/login.ts` (hh) / `... careerist` |

Повседневный цикл целиком — `Запустить.cmd` в корне проекта: проверяет окружение,
чистит залипший браузер, ищет, открывает панель. Отправки там нет намеренно.

`--limit` — это ЗАКАЗ, а не потолок просмотра: «набери столько вакансий в
очередь». Поиск сам решает, сколько выдачи для этого прочитать, листает
порциями и делит заказ поровну между формулировками запроса; если у одной
формулировки выдача кончилась, её долю добирают остальные. Предохранитель от
бесконечного листания — потолок просмотра (сорок карточек на каждую заказанную,
но не меньше двухсот); когда прогон упёрся в него или в конец выдачи, он
называет это в отчёте, чтобы недобор не выглядел как «больше ничего нет».

То же число вводится в панели, в правом верхнем углу.

## Что показывать пользователю

`npm run panel` и открой `http://127.0.0.1:4321`.

Для быстрой сводки без панели:


## Прокси: раздельная маршрутизация

Проверено живьём 2026-09-01, по каждому адресату отдельно:

| адресат | напрямую | через прокси |
|---|---|---|
| OpenRouter (письма) | **403 блок-страница** | 200 |
| hh.ru | 200 | **403** |
| careerist.ru | 200 | **ConnectTimeout, 3 из 3** |
| hr.ge | 200 | 200 |

То есть **ни «всё через прокси», ни «всё напрямую» не работает.** Прокси нужен
ровно одному адресату — OpenRouter; площадкам он ломает связь.

Поэтому через прокси идёт ровно один запрос — письмо (`generateLetter` по
умолчанию берёт `createProxiedFetch`), а всё остальное напрямую. Переменные
окружения, `NO_PROXY` и `--use-env-proxy` больше не используются: до
2026-09-18 их задавали лаунчеры, один раз и с зашитым портом `10801`, и когда
VPN-клиент переехал на `10809`, письма встали.

Где ищется прокси, по порядку (`discoverProxy`):
1. `HTTPS_PROXY`/`HTTP_PROXY`, если заданы;
2. `ProxyServer` из настроек Windows — туда порт пишет сам VPN-клиент;
3. порты, которые слушают процессы xray/v2ray/sing-box/clash/mihomo
   (`netstat` + `tasklist`) — на случай, если в реестре старый порт;
4. запасной `10801`.

Каждый кандидат проверяется `CONNECT openrouter.ai:443`: открытого порта мало,
рядом с HTTP-портом у клиента обычно слушает SOCKS. Результат живёт 10 секунд;
если прокси подвёл посреди работы, следующий запрос ищет заново.

**Браузер — отдельная история.** Chromium берёт прокси из НАСТРОЕК WINDOWS, а
не из переменных окружения, и у владельца там постоянно включён VPN-клиент
(`ProxyEnable=1`, `127.0.0.1:10801`). Через него careerist.ru в браузере даёт
`ERR_TIMED_OUT` — то есть подача на careerist ломалась бы молча. Поэтому
профиль запускается с `--no-proxy-server` (`profileLaunchOptions` в
src/browser.ts): браузер ходит только на площадки, прокси ему не нужен
никогда. `proxy: { server: 'direct://' }` для этого НЕ годится — Playwright
его принимает, Chromium отвечает `ERR_PROXY_CONNECTION_FAILED`.

Итого: браузер всегда напрямую, fetch тоже напрямую, кроме запроса письма —
только он идёт через найденный прокси.

**Короткий ответ на «работает ли без прокси»:** работает всё, кроме генерации
писем. Поиск, скоринг, фильтры, панель и подача — не трогают OpenRouter.

## Настройки поиска: специальности и стоп-слова

С 2026-09-18 то, что было зашито в код под бизнес-аналитика, лежит в
`data/settings.json` и правится во вкладке панели **«Настройки»**. Спека —
`docs/superpowers/specs/2026-09-18-search-settings-telegram-autoapply-design.md`,
раздел 3. Файл вне git; при первом запуске засевается из `config.json#searchQueries`
один раз (фразы с `juniorOnly` → «Системный аналитик», остальные → «Бизнес-аналитик»),
после этого `searchQueries` в `config.json` ни на что не влияет.

**Специальность** — фразы поиска, слова заголовка, навыки с весами, «мой опыт, лет»,
PDF резюме. Поиск идёт по фразам всех включённых специальностей; вакансию оценивает
специальность той фразы, что её нашла.

- **Навыки и веса.** Навык совпал, если в тексте есть любой его синоним. Скор =
  `min(100, round(совпавшие_веса × 113 / сумма_весов))` — для БА это ровно прежние
  числа (проверяет `tests/scorer-parity.test.ts`). «Ядро» — галочка: без единого
  совпавшего навыка-ядра вакансия отсекается. Вес 0 выключает навык.
- **Слова заголовка.** Заголовок обязан содержать одно из них. Скор говорит, ЧЕМ
  занимаются; заголовок — кем зовут: «Менеджер по операционному консалтингу»
  набирал проходной скор процессной лексикой. У БА слова — «аналитик», «analyst»,
  «BA», «SA».
- **Опыт.** Вакансия проходит, если её минимальное требование не выше «мой опыт»
  (без опыта = 0, 1–3 = 1, 3–6 = 3, 6+ = 6; не указано — проходит). У БА 2 — ровно
  прежнее «1–3 года или меньше». **Опыт 0 — это прежний `juniorOnly`**: проходит
  только «без опыта», и отсекается «старший/senior/middle» в заголовке (у «Системного
  аналитика»). Владелец отправил отклик на «Старший ИТ аналитик» в тот же день, когда
  отменил «Старший системный аналитик» — поэтому «старший» режется только при опыте 0.
- **Письма.** Засеянные специальности (`legacyLetters`) пишут как раньше: скелеты
  `templates/`, hybrid/full по скору, резюме из `CV …Бизнес-аналитик.md`. Новые —
  всегда целиком, по тексту своего PDF (кеш в `data/resumes/<id>.txt`).
- **«Предложить»** — одна модель по резюме заполняет слова заголовка и навыки; ответ
  попадает в форму несохранённым. Нужен VPN, как письмам.

**Стоп-слова** — общий список (засев: 1С, Битрикс, Bitrix). Отсев, если слово в
заголовке **или** 2+ раза в описании. Одно упоминание в списке систем («Jira, 1С,
ELMA») не режет. Для 1С это строже прежнего порога 3 — осознанно.

Правила совпадения слов (`src/core/matching.ts`): регистр не важен; 1C = 1С; слово
ищется с начала слова («битрикс» ловит «Битрикс24»); русское слово от 5 букв теряет
окончание («процессная модель» ловит «процессной модели»); аббревиатура заглавными и
слова до 3 букв — только целиком («REST» не ловит «restrictions»); `*` — любые буквы
дальше; дефис во фразе — только дефис.

**Остались в коде:** отсев стажировок (владелец: «стажерская вакансия не по
профилю»; это отменяет прежнее правило письма про junior+/middle) и грейдов
lead/head/ведущий/руководитель в заголовке.

## Известные пробелы

Говори о них честно, не выдавай систему за законченную.

- **Капча у hh.ru не распознаётся.** Маркер не снимался живьём, а выдуманный
  селектор хуже отсутствующего: он молча не совпадёт никогда. Вместо этого стоит
  предохранитель — три отказа подряд по одной площадке гасят её (площадку, не
  прогон: остальные продолжают).
  «Вы уже откликались» — снято 2026-09-01, работает, см. docs/hh-selectors.md.
- **Подача на hr.ge не реализована.** Возвращает честный отказ со ссылкой «подай
  вручную»: снять контракт значит отправить настоящий отклик работодателю.
- **careerist.ru умеет и искать, и подавать** (с 2026-08-31, пользователь
  зарегистрировался и залогинился). Письмо там уходит ВМЕСТЕ с откликом — приятное
  отличие от hh.ru. Успех проверяется по разделу `/responds/`, а не по строке в
  ответе. Живые подачи прошли: 6 откликов на 2026-09-01.
- **Письмо на hh.ru уходит вторым шагом**, отдельным сообщением в чат. Маршрута, где
  оно уходит вместе с откликом, у hh.ru нет — проверено.
- **Пороги не откалиброваны.** `letterFullThreshold` равен 75, а живые скоры выходят
  52–64, то есть режим `full` включается редко.
- **Резюме на hh.ru — от аккаунта hh, а не от специальности.** PDF специальности
  идёт в письмо (и дальше — в Telegram), но отклик на hh уходит с резюме, выбранным в
  аккаунте hh. Отклик на «менеджера продукта» с hh может уйти с резюме БА. Как адаптер
  выбирает резюме, когда их в аккаунте несколько, не снято.
- **Две модалки hh.ru не поддержаны.** Часть вакансий при клике «Откликнуться»
  открывает окно: либо с обязательным сопроводительным, либо с вопросами
  работодателя (свободный текст и чекбоксы). Такие подачи падают отказом «клик не
  привёл к подтверждению». Снять контракт нельзя без ссылок на конкретные вакансии
  от владельца: клик по «Откликнуться» для ЧАСТИ вакансий и есть подача, и на этом
  уже один настоящий отклик ушёл по ошибке.
